## 1. 摘要

本报告提出并分析了一种利用现代显示屏和摄像头进行数据高速传输的多维光场编码方案。该方案在传统二维码（QR）的空间二维（X，Y）基础上，引入了**广义形状**（像素块内二值图案）、**颜色与亮度复合调制**以及**时间维度**（帧序列），构造出 **5 个独立信息维度**。通过严格的香农信息论建模，给出其理论传输速率的闭合表达式。结果表明，即使在码元块尺寸较大、易于工程实现的条件下，传输速率仍可维持在一个极高的下限值，远优于现有商用动态二维码技术。本报告为该方案作为“任意文件异步编解码网页”的后端理论支撑提供了完整的数学框架和最优参数选择依据。

## 2. 引言

传统静态二维码的信息容量有限（例如 QR 码 Version 40 最大约 3 KB），且传输依赖多次扫读。动态二维码（如刷新屏幕）虽能提升速率，但受限于码元单一（黑白）的信息密度。近年出现的彩色码（如 CIMBAR）虽引入颜色维度，却忽视了像素块内部空间排布（形状）所蕴含的惊人信息潜能。

本方案旨在设计一种通用的视觉透传协议，使任何文件均可通过“屏幕播放编码帧序列 → 摄像头采集解码”的方式实现异步传输（即编码与解码可分离，无需实时交互）。其理论速率可轻松覆盖 **数 Mbps 至上百 Mbps**，满足绝大多数中低数据量文件的秒级传输需求。

## 3. 编码方案定义

### 3.1 空间维度（X，Y）

- 将整个画面划分为若干独立的 **码元单元（symbol）**，每个码元占据一个边长为 **a** 像素的正方形区域（a ≥ 1，a 为整数）。
- 画面总分辨率为 **R×R** 像素（本报告以 R=512 为基准，但公式对任意 R 通用）。
- 有效码元总数（忽略定位标记等开销）：  
  \[
  N = \left(\frac{R}{a}\right)^2 = \frac{R^2}{a^2}
  \]

### 3.2 形状维度（广义二值图案）

每个码元内部（共 a² 个像素）的每个像素可取“亮”或“暗”二值状态。所有可能图案的总数为 **2^{a²}**（包含全暗/全亮等所有组合）。  
该图案作为形状信息载体，其信息量为：  
\[
I\_{\text{shape}} = \log_2(2^{a^2}) = a^2 \quad \text{比特}
\]  
此定义消除了传统“非空图案”的约束，全暗状态也被赋予明确信息含义，使公式达到精确闭式。

### 3.3 颜色与亮度复合维度

每个码元整体附加一个颜色与亮度组合状态。

- 亮度等级：8 级（0~7）
- 基本颜色：8 种（例如红、绿、蓝、青、品红、黄、白、黑）
- 总状态数：8×8 = 64
- 信息量：  
  \[
  I\_{\text{color_brightness}} = \log_2(64) = 6 \quad \text{比特}
  \]  
  （注：该数值可根据实际显示与摄像头的色域动态调整，但本报告采用此典型值。）

### 3.4 时间维度（帧序列）

通过连续播放多帧画面（帧率 **F**，帧/秒），每帧独立承载上述静态信息，形成数据流。实际传输时，数据被拆分为若干帧，每帧为一幅完整编码图像。

## 4. 理论传输速率推导

### 4.1 单帧信息量

每个码元承载总比特数为：  
\[
I*{\text{symbol}} = I*{\text{shape}} + I*{\text{color_brightness}} = a^2 + 6
\]  
单帧画面总信息比特数：  
\[
B*{\text{frame}} = N \cdot I\_{\text{symbol}} = \frac{R^2}{a^2} (a^2 + 6)
\]

### 4.2 传输速率公式

数据速率（比特每秒）为：  
\[
\text{Speed (bps)} = B\_{\text{frame}} \times F = \frac{R^2}{a^2} (a^2 + 6) \cdot F
\]  
化简得核心公式：  
\[
\boxed{\text{Speed (bps)} = R^2 \cdot F \cdot \left(1 + \frac{6}{a^2}\right)}
\]  
或表示为 Mbps：  
\[
\text{Speed (Mbps)} = \frac{R^2 \cdot F}{10^6} \cdot \left(1 + \frac{6}{a^2}\right)
\]

### 4.3 重要特性

- 当 **a** 增大时，\(\frac{6}{a^2}\) 迅速衰减，速率趋近于一个 **下限值**：  
  \[
  \lim\_{a \to \infty} \text{Speed} = \frac{R^2 \cdot F}{10^6} \ \text{Mbps}
  \]  
  即仅由分辨率和帧率决定，与码元大小无关（只要 a 足够大）。
- 当 **a = 1** 时，速率达到理论最大值：  
  \[
  \text{Speed}\_{\max} = \frac{R^2 \cdot F}{10^6} \cdot 7 \ \text{Mbps}
  \]  
  比下限值高出 7 倍。

## 6. 异步编解码的适用性

“异步”意指编码方（发送端）与解码方（接收端）无需实时同步，解码可在任意时刻通过拍摄已编码的视频流（或屏幕录屏）完成。

- **编码端**：将任意文件二进制流分段，每段映射为多帧编码图像，可保存为视频文件或实时播放。
- **解码端**：通过手机摄像头拍摄屏幕，或直接读取视频文件，逐帧提取码元并还原比特流。
- 异步特性使得该方案可离线使用（如预存视频，事后扫描），且解码不依赖网络。

## 7. 现实约束与误差考虑

1. **摄像头感光特性**：CMOS 拜耳滤镜会使单像素颜色插值产生偏差，故 **a ≥ 8** 时颜色和形状识别更可靠。
2. **屏幕子像素排列**：RGB 条状或钻石排列会影响色度重现，需在解码端进行校准或使用纠错码。
3. **运动模糊**：高帧率下若相机抖动，可采用电子防抖或降低帧率（如 30 fps），此时速率约 8.6 Mbps（a=8），仍远高于二维码。
4. **计算负载**：解码算法需对每帧进行码元分割和形状识别（连通域分析），现代手机 SoC 可轻松实时处理 60 fps 的 512×512 图像。

## 8. 结论

本报告提出了一种新的多维视觉编码方案，其核心创新在于将“形状”广义化为像素块的所有二值图案，使其信息量随块面积线性增长，从而保证在增大码元尺寸以提升鲁棒性的同时，传输速率几乎不下降。

理论推导显示，该方案在常用分辨率（512×512）和帧率（60 fps）下，采用 a=8 的码元块即可达到 **17.21 Mbps** 的稳定传输速率，接近物理极限。该速率足以满足多数文件异步传输场景，且解码复杂度可控，适合在普通网页前端（通过 WebRTC 或屏幕捕获 API）实现。

本报告为后续开发“任意文件异步编解码网页”提供了坚实的数学基础和参数选择策略。下一步工作将聚焦于编解码算法的具体实现、纠错码集成以及跨平台兼容性测试。

## 浏览器编解码器

仓库的 [`site/`](./site/) 是一个不依赖后端和构建工具的静态网页，实现了：

- 任意类型文件 → 浏览器原生 GZIP 压缩 → 6D 码元映射 → 无损索引色 APNG、MOV 或 AVI；
- MOV 使用 QuickTime 容器中的逐帧 PNG 无损视频轨道，可由 QuickTime、VLC、FFmpeg 等兼容工具读取；
- AVI 使用 8-bit 索引色 DIB 帧并内嵌调色板，优先兼容 Windows 自带播放器；
- APNG / MOV / AVI → 逐帧 CRC32 校验 → GZIP 解压 → SHA-256 校验 → 原文件；
- 分辨率、码元边长、帧率以及 8×8 颜色/亮度调色板的可视化调节；
- 左上、右上、左下三个 7×7 定位点。定位结构已预留，但当前版本不支持摄像头或移动端动态扫码。

所有文件数据均在浏览器本地处理，不会上传到服务器。推荐使用最新版 Chrome、Edge 或 Firefox。大文件会在浏览器内产生明显大于原文件的 APNG、MOV 或 AVI，这是像素载荷密度与无损图像/视频容器共同决定的正常开销。AVI 的索引色帧不做视频层压缩，但每像素仅需 1 字节，约为旧 RGB24 AVI 的三分之一，并优先保证 Windows 播放器兼容性；MOV 的浏览器内预览兼容性有限，但不影响下载、播放或由本站解码还原。
